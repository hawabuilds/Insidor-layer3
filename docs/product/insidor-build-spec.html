00 — WHAT CHANGED

Three findings that move the plan

1 · The 40% poster split is natively supported. Better than Bags.

I previously called this a showstopper — that no Solana primitive could route fees to a poster who never consented and has no wallet. That was wrong. Pump.fun ships an on-chain, permissionless creator-fee-sharing system: create_fee_sharing_config → update_fee_shares_v2 → distribute_creator_fees_v2. It splits creator fees across up to 10 arbitrary pubkeys in basis points summing to exactly 10,000. No rule ties a shareholder to the creator identity — any pubkey qualifies.

Better still: create_v2 takes creator as a plain Pubkey argument independent of the signing user. Insidor can pay for and sign a launch while assigning creatorship elsewhere. That single fact is the most valuable thing in the research.

2 · Photon and Axiom have no public API. Feature 2 cannot start as written.

Not "hard to get" — does not exist. Axiom's own complete docs index (llms.txt, which enumerates every page they publish) contains zero developer, API, SDK or webhook entries. Photon's official GitBook has no developer content, and QuickNode's directory states flatly that Photon "does not support API integrations or Telegram bots." Both are Cloudflare-gated closed frontends.

There is no "integrate whichever is cheaper" decision to make, because there is nothing to price. The community "Axiom SDKs" require storing users' Axiom passwords, reading their email for login OTPs, and running headless Chrome past Cloudflare. Not shippable in a consumer product.

The replacement is strictly better on the axis you cared about: Photon charges your user 1% per buy and per sell and pays Insidor nothing. Jupiter lets you set your own integrator fee. You capture revenue from day one — which deletes the "build our own terminal later to take all fees" milestone.

3 · "Search PF metadata" is not a thing you can call. You're building an indexer.

The pump.fun SDK is transaction-building only — no search, no discovery, no metadata query. The endpoint that used to do ticker search, frontend-api-v3.pump.fun/coins/search, is dead as of this research. On-chain you get only a uri string; the image sits one HTTP hop deeper inside the IPFS JSON.

Match-by-image is a genuinely good idea — it fills the one hole a previous engineering review found that nobody had specced. But it is not a 3-week feature. It is a corpus you build and keep fresh.

The moderation trap — this is where products in this category die

Every off-the-shelf moderation API — OpenAI, Perspective, Azure, Hive — classifies hate, violence and sexual content, and detects exactly zero of the harms that will actually appear: contract-address spam, honeypot shilling, founder impersonation, coordinated pumps. The crypto-native layer has to be built in-house.

Also: Perspective API sunsets 31 Dec 2026 and closed quota increases in Feb 2026. Any plan naming it must be rewritten.

Read this before putting a comment box under an X post

X's Display Requirements, verbatim: "No other social or third party actions may be attached to a post. (e.g., subscribe, comment, like)." Attaching an Insidor comment thread directly to a displayed X Post is a literal violation. Attach comments to the narrative — your own object — not to the rendered Post.

F1.4–6Ranking, tags, rev-share, profiles, flex cards LATER
Thumbs up/down, name tags, revenue share for top-ranked users.
Design around this before you build it

Rev-share for commentary that promotes tokens Insidor earns trade fees on triggers FTC Endorsement Guides obligations (disclosure program, monitoring, penalties $51,744–$53,088 per violation) and CFTC Rule 180.1 spot-manipulation exposure. It is also the exact shape X deleted the InfoFi category over.

The distinction that may save it: rewarding posting on Insidor is not rewarding posting on X. That distinction is ours, not X's, and it has never been tested. Keep it LATER — you were right to.

F3.xThe poster's 40% — now buildable DECIDE
// creator fee sharing — permissionless, on-chain
create_fee_sharing_config   // PDA seeds [b"sharing-config", mint]
update_fee_shares_v2        // set the split — SEE WARNING
transfer_creator_fees_to_pump_v2
distribute_creator_fees_v2  // permissionless, pro-rata, creates missing ATAs

// rules: max 10 shareholders · no duplicates · each > 0 · sum EXACTLY 10,000 bps
[ creator 5000 · poster 4000 · insidor 1000 ]  // = 10,000 ✓
The constraint that shapes the whole flow

update_fee_shares_v2 sets admin_revoked = true — treat the split as set-once, at launch. You cannot launch now and add the poster later when they show up.

The architecture that solves it: at launch time, deterministically derive a Privy embedded wallet from the poster's social handle and set that address as the shareholder. The wallet is addressable on-chain before the human has ever logged in, and distribute_creator_fees_v2 will happily pay a wallet nobody has claimed. The money sits there until they arrive.

Verify the exact revocation semantics against the live program before building on this — the fact-check flagged the consequence as possibly overstated.

Two footguns

1. Creating a sharing_config permanently disables collect_creator_fee_v2 for that mint. If your distribution cranker breaks, there is no fallback collection path. Build and monitor it before you ship a single shared coin.

2. PDA seeds differ between programs: [b"creator-vault", creator] on Pump vs [b"creator_vault", coin_creator] on Pump AMM. Hyphen versus underscore. An easy and expensive bug.

Published near-duplicate thresholds come from DISC21 — transformed Flickr photos, not memes with text overlay and AI-generated logos. A tight crop of one face from a source image defeats global descriptors roughly half the time. Hand-label a few hundred real post→token pairs and fit your own cutoff. Don't ship a borrowed number.

The $1M/month volume ceiling. 500 real traders averaging $2,000/mo of volume hits it. Usage billing starts there — model it now, not when the invoice lands.

06 — SEQUENCE

What to build, in order

The three-week clock is real, but it applies to the trading terminal, not the indexer.

WEEK 0

Kill the assumptions

Three cheap checks before code. Quote a seconds-old token through Jupiter and read the actual platform fee (10 bps or 50 bps — docs and live behaviour disagree). Call pump.fun/api/ipfs and confirm it still accepts uploads. Read the live update_fee_shares_v2 semantics on devnet to confirm exactly how one-shot the split is.

WEEK 1

Trading, in a day — then the corpus

Jupiter Plugin embedded in the feed with enableWalletPassthrough into Privy. DexScreener iframes for charts. Jupiter toptrending for coin data. That is Feature 2 and half of Feature 7 done in week one. Spend the rest of the week streaming create_v2 instructions into your token index.

WEEK 2

Wallet, create, watchlist

Privy embedded wallets. Pump.fun createV2Instruction with the fee-sharing config wired to a poster-derived wallet. Watchlists for posts and coins.

WEEK 3

Comments, with moderation on day one

Supabase Realtime Broadcast, spend cap off. Ship the crypto-native filter in the same release — CA regex, impersonation checks, rate limits. Never after.

WEEKS 4–7

The indexer and image matching

Backfill and embed the filtered token corpus. Build the combined image + ticker + text scorer. Hand-label your own evaluation set and fit the threshold. Search (F6) ships on top of this.

LATER

Trenches, ranking, profiles, flex cards

As you had them. Take legal advice on rev-share before designing it, not before shipping it.

08 — BEFORE YOU WRITE CODE

Verify these five

Adversarial fact-checking refuted 15 of 26 specific claims in this research — not the conclusions, but the exact endpoints, prices and method names. APIs in this space move weekly. Treat every code identifier here as needing confirmation on the day you use it.

  • The Jupiter new-token fee. Docs say 50 bps under 24h; the live API returned 10 bps. Quote a real new token and measure. This decides your margin.
  • The fee-split revocation semantics. How genuinely one-shot is update_fee_shares_v2? Test on devnet. It determines whether the poster wallet must be derived at launch.
  • Whether a shareholder wallet can be one nobody has claimed. The whole 40% mechanic rests on paying an address before its human exists. Prove it on devnet with a fresh keypair.
  • X pay-per-use eligibility for a new developer account. The 2M ceiling and the inability to buy Basic are the constraints that shape the product.
  • Whether Photon or Axiom have a private partner API. Public: definitively no. Behind a BD email: unverified. One message answers it, and it would change Feature 2.
09 — LEGAL

Three things to take advice on

  • Paying a poster who never consented. Now technically easy, which makes the legal question the binding one. Right of publicity is state law with no federal statute, and consent is the primary defence. Ship the opt-out registry and the "not created or endorsed by" disclaimer in the same release as the split.
  • Rev-share for commentary. FTC Endorsement Guides plus CFTC Rule 180.1 when you also earn fees on the thing being promoted. This is why it stays LATER.
  • Comments attached to X content. The Display Requirements prohibition is explicit. Attach threads to your narrative object, never to the rendered Post.
