1. Project overview

Insidor is a narrative-first Solana memecoin discovery and trading UI prototype. It surfaces viral social posts (X, TikTok, Reddit, Farcaster, Telegram), clusters them into narratives, links them to tokens (live or candidate), and provides simulated deploy/buy flows.

All market and social metrics are mock/simulated in the current build — the UI is designed to show the intended product experience before real APIs are wired in.

5. Data models

NARR[] — viral post feed (10 items)

Raw posts for rail, deploy source, trending cards.

{ plat, badge, lead, txt, views, posts, accts, peak, vel,
  who, at, t, pal, media }  // media: photo|video|link|reply|none

Platforms: x, tt, rd, fc, tg. Tickers in text as $TICKER.

TOKENS[] — live coins (10 seeded)

{ sym, name, ca, price, c5, c1h, c24, vol, liq, mc, ageM,
  lead, narrIdx, holders, live, txns,
  socials: { web, x, tg }, dex, pump,
  mintRevoked, freezeRevoked, lpBurned, top10, justDeployed? }

Created via mkToken(sym, name, seed, narrIdx, lead).

PENDING{} — candidate tickers (no coin yet)

PENDING[sym] = { narrIdx, lead }

Shown in New Pairs, Launches rail, deploy availability checks. Starts empty in production site.

NARRATIVES[] — clusters (14 items)

{ id, title, blurb, imgSeed, image, createdAt, narrIdx,
  searchSeries, leadTimeMin, organicScore,
  posts: [ seedPost(...) ],
  tokens: [ seedTok(...) ] }

Example IDs: ferry-horn, norway-move, porch-frog, office-meme, etc.

Clusters without live tokens show a Create button instead of mcap.

seedPost() → post object

{ platform, handle, followers, text, image,
  views, replies, quotes, notable, sampleReplies[], postedAt }

seedTok() → narrative token metadata

{ ticker, name, mcap, liquidity, vol24h, holders, ageMin,
  firstDeployed, endorsedBy, canonical,
  safety: { mintRevoked, lpBurned, topHolderPct, ... },
  smartMoney: { smartWalletsIn, holderGrowth1h, topTraders[] } }

Key helper functions

  • getNarrative(id), narrTopPost, narrTopToken, narrCombinedViews
  • narrViralGain24h, narrLifecycle → heating|peaking|cooling
  • extractTickers(txt) — regex \$[A-Z]{2,10}
  • deriveTicker(txt) — longest 3–10 letter word
  • syncNarTokens() — sync narrative token mcap from live TOKENS
  • narrativeForToken(t), tokenOriginStrip(t) — token page → narrative link

8. UI components & sorting

Layout

  • .shell — CSS grid: main + 460px rail
  • .view.on — active main section
  • .ttable + .thd / .nthd — data tables

Sort systems

  • Narratives: chips New | Trending; columns views, gain, mcap, age
  • Tokens: chips Hot (vol) | Gainers (c24) | New (ageM); column override via header click
  • New pairs: always newest first (ageM); column sort optional
  • trendScore(t): weighted vol/mc + txns + c24 + c1h

Visual components

  • sparkSVG(t) — 24h mini chart in token rows
  • narrSparkSVG — narrative search trend sparkline
  • starTok / starNarr — watchlist toggles
  • .pbadge — platform badges (X, TikTok, etc.)
  • .tp-origin — token page source narrative strip

9. Auth & wallet (Privy)

Meta tags: privy-app-id, privy-client-id in HTML head.

React module mounts PrivyProvider into #userAuth:

  • Unauthenticated → Connect button → login()
  • Authenticated → user chip (Google name / email / wallet) + logout
  • Fallback if file:// or SDK load failure

Trade execution is mock — #exec simulates confirm after 700ms. Copy references user signing in their own wallet.

12. Future backend considerations

For a production architecture, expect to add:

  1. Narrative ingestion pipeline — scrape/API feeds from X, TikTok, Reddit; cluster into narratives
  2. Token index — DexScreener/Birdeye/Helius for live prices, liquidity, safety scores
  3. Deploy service — pump.fun or custom mint; wallet signing via Privy embedded wallet or external
  4. Trade execution — Jupiter or Raydium swap API; slippage/priority fee handling
  5. User persistence — watchlists, preferences, deploy history (DB + auth user ID from Privy)
  6. WebSocket feeds — live trades rail, price ticks, new pair launches
