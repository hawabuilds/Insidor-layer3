ANATOMY 01

The stamp

Every comment records the state of the narrative at the moment it was written — views, coin count, age. A take posted at 340K views with no coin is worth more than the same words at 2.4M with three coins. It makes earliness visible and permanent, which is the product’s whole thesis applied to people.

ANATOMY 02

The position badge

Insidor knows the commenter’s wallet and can read their holdings on-chain, so every comment shows whether they are talking their book — holds 2.1 SOL, no position, or sold. No other comment section in crypto can do this, and it is the single most useful fact about any opinion on a coin.

02 — THE OBJECT IT ATTACHES TO

Comments belong to the story, never the post or the coin

Not the post — this is a hard rule

X’s Display Requirements, verbatim: “No other social or third party actions may be attached to a post. (e.g., subscribe, comment, like).” Hanging an Insidor thread off a rendered X Post is a literal violation of the terms that keep your ingestion alive.

Not the coin either — this one is product, not policy

One story can spawn several coins. If discussion attaches to coins, it fragments across duplicates — three threads about the same ferry captain, each half-dead. Attach to the story and the conversation stays whole while coins come and go beneath it.

It also means a story with no coin yet still has a discussion — which is exactly where the earliest and most valuable takes happen.

-- one table, attached to the story
create table comment (
  id            uuid primary key,
  story_id      uuid not null references story(id),  -- never post, never coin
  author_id     uuid not null references app_user(id),
  body          text not null,
  created_at    timestamptz default now(),

  -- THE STAMP: narrative state frozen at write time. denormalised on purpose --
  -- it is a historical fact, not a join. it must never change.
  snap_views      bigint,
  snap_coin_count int,
  snap_age_min    int,
  snap_top_mcap   numeric,

  -- THE POSITION: read from chain at write time, same reasoning
  snap_position_lamports bigint,
  snap_position_mint     text,

  status        text default 'visible',  -- visible | held | removed
  flags         jsonb
);

create index on comment (story_id, created_at desc);
create index on comment (story_id, snap_views asc);  -- "earliest takes" sort
03 — MODERATION

Structural, not a classifier

No moderation vendor detects the harms you will actually get. But you do not need a model — you already have the story’s coin index, and that turns the main attack into a database lookup.

The insight that makes this cheap

The dominant attack is contract-address shilling: someone drops a CA for their own unrelated coin under a hot narrative. Insidor already knows every mint matched to that story. So:

If a comment contains a Solana address that is not one of this story’s coins, it is a shill. No ML, no vendor, no false-positive tuning. One lookup against a table you built for a different feature.

-- the whole crypto-native filter, in order of cost

1. ADDRESS GATE   base58 string, 32-44 chars, in the body?
                  and not in (select mint from coin where story_id = $1)
                  -> block, no appeal. this is 90% of the spam.

2. IMPERSONATION  handle within edit-distance 2 of the story's poster,
                  or of a top-50 known account, and not verified as them
                  -> hold for review

3. WALLET AGE     wallet < 24h old and zero prior transactions
                  -> rate limit to 1 comment per story, held if links present

4. VELOCITY       > 3 comments / 60s per wallet, or the same body text
                  posted under > 2 stories in 10 min
                  -> silent drop, no error shown to the poster

5. GENERIC        an off-the-shelf API for hate / violence / sexual
                  -- necessary but catches none of 1-4
Two operational rules

Ship the filter in the same release as the comment box. Never after. A crypto comment section left open for one week without one is unrecoverable — you will be cleaning it up forever.

Require a connected wallet to post. Not for identity, for cost. It is the cheapest sybil resistance you have, and you already have Privy.

05 — WHAT COMES LATER

Ranking, built on the stamp

Why the stamp makes ranking non-gameable

You planned thumbs up/down and rev-share for top users. Upvotes are trivially farmed. But the stamp gives you something better and already recorded: for every comment on a story that has since played out, you know the narrative state when it was written and what happened after.

So a user’s score is not “how many likes” — it is “how early were they on things that worked, across how many independent stories.” You cannot farm that without actually being right, early, repeatedly.

But keep rev-share switched off until counsel has seen it

Paying users for commentary on tokens you earn trading fees on triggers FTC Endorsement Guides obligations and CFTC Rule 180.1 exposure. It is also the exact shape X deleted an entire app category over in January. Build the score, display the score, do not pay for the score yet.
