13. How each part gets built

Eleven steps. Each one ships on its own and is useful on its own, and each one ends with a test that either passes or does not — never with somebody deciding it feels finished.

A build plan written as a list of things to make is a wish. The same plan written as a list of things to prove is a schedule. So every step below carries a done when line, and every one of those lines is something a machine can check: a query that returns the right shape, a test that goes red when a threshold moves, a folder whose diff is empty. Nobody has to judge whether the storyteller is good enough. Either the gold set produces a curve or it does not.

The order is not a preference. It comes from one fact: three of the five data streams this business depends on are not being recorded at all today, and a fourth deletes itself every twelve hours. Code can be written later. A week of mint times that were never written down is gone forever. So the steps that start a recorder come before the steps that build anything to look at, even though the recorders produce nothing a person can see.

Three things to notice before the list

Step 1 · counter-intuitive

It goes into the old build

The decision log is retrofitted into the pipeline running right now, not the new one. That pipeline makes a few thousand judgements a day and writes down none of them. Every day spent building the replacement first is another day of training data thrown away.

Step 2 · cannot move

Mint time is a deadline

Ten of the eleven steps can be reordered under pressure. This one cannot. Without a stored mint time there is no way to say afterwards whether a call was early or late — so every day it is not running is label data that will never exist, at any price.

Step 10 · the exam

TikTok is the test, not a feature

Adding the second platform should be one new folder and one new line. If it has to touch the thinking layer, the whole design failed — and it failed cheaply, three days in, instead of a year later when someone says a new platform is a rewrite.

Read the diagram as three lanes that run mostly in parallel. The top lane is the machine that finds things — collector, tracker, storyteller, and the screen people look at. The middle lane is the money path — knowing when a coin appeared, then choosing the right one, then putting a Buy button next to it. The bottom lane is the part that lets the system get better over time — write down every judgement, join it to what actually happened, then let a model learn the join. The lanes touch in only two places, and both are drawn dashed, because both are the kind of dependency people forget and then discover late.

The eleven steps

Step0~2 daysFoundation
The skeleton and the gates

Nine folders with rules about which may talk to which, one file holding every threshold in the system (today there are sixty of them typed into twenty-four different files), six automated checks, and the current build moved wholesale into a folder called legacy/ where it keeps running untouched.

UnblocksEverything. Boundaries added after the code exists never actually get added — they get argued about and waived.
Done whenA change that lets vendor code reach into the decision code fails the build and names the rule it broke.
Step1~3 daysPerishable
The decision log — into the build that is running todayHighlight 1

Three tables and one small writer, wired into the existing cron runner and the existing gate functions. Nothing is rewritten. Every judgement gets stored with what it saw, what it chose, and which thresholds it was judged against. The 2% holdout and the 5% exploration reservation land in the same commit, because a log of decisions you always would have made teaches nothing.

UnblocksReplay, the first training set, and the first model roughly five months out. It also fixes a live bug: a stage that dies mid-run currently looks identical to a stage that ran and found nothing.
Done whenOne query separates ran and found nothing from died, and a process killed halfway through leaves its row with no finish time rather than no row at all.
Step2~2 daysCannot move
Mint time, stored, with a source attachedHighlight 2

A table of coins, filled by polling the launchpad's own list and confirming each one against a single generic chain call — plus a coverage log, so a stretch where the poller was down is recorded as we were not watching rather than quietly counted as no coin existed. That second half is the whole point: the failure to avoid is a gap that flatters us.

UnblocksEvery outcome label, the rule that stops us claiming credit for something posted after the coin, and every how-far-into-the-run number the product will ever publish — a coin's age against a six-day arc is the whole reason a user can tell a run that is still climbing from one that is over.
Done whenA gap induced on purpose produces a coverage row, and the labeller marks that window unmeasurable instead of scoring it as a miss.
Step3~5 daysPipeline
The collector

The X connector and the first decision stage — is this worth spending money to watch? — running alongside the old ingest without replacing it. Critically, a second connector ships in the same step: a fake platform backed by recorded files. An interface with one implementation is always secretly shaped like that implementation.

UnblocksStep 10, which is only cheap because a second implementation already exists. It also gives the testing tools a data source that needs no network and no vendor bill.
Done whenOne test suite passes unchanged against both the real platform and the recorded one, and no platform's name appears anywhere in the thinking layer.
Step4~5 daysPerishable
The tracker and the honest counters

When to look at a post again, how to store each reading, and the rule that says a rounded counter which has not visibly moved means we learned nothing — not that the post is cooling. Today the system publishes a zero there, and zero reads downstream as fading, which demotes exactly the posts that are picking up speed.

UnblocksEvery speed-of-growth signal, and the curve the board is built on. Perishable: a day not shipped is a day of curve data that will never exist.
Done whenA rounded counter whose change is smaller than its rounding step records censored: below step — and no rate at all.
Step5~4 daysMoney path
The resolver — which coin, if any

Eight checks in cheapest-first order, candidates generated by time rather than by name, a margin rule so two plausible coins produce no answer instead of a coin flip, and a hard split between a ticker we actually saw and a ticker we guessed. This is the only step where being wrong costs a user money — 189 of 323 currently resolved tickers share no words at all with the story they are attached to, and a working swap sits one click away.

UnblocksTurning the Buy button back on without it being wrong. Nothing else in the plan is allowed to ship a Buy affordance before this.
Done whenA frozen set of the real past mistakes runs on every change, so a threshold cannot be nudged silently.
Step6~7 daysPipeline
The storyteller

Deciding that forty posts are one story rather than forty stories. The free, deterministic signals first and alone — the same image, the same phrasing, the same sound or effect — measured before any meaning-matching is switched on. The English-only filter comes off in the first hour of this step; it currently appears in two places, so removing one leaves half the funnel shut while looking fixed.

UnblocksGrouping across platforms, which is the product's actual premise. Today the grouper leaves 91% of stories with exactly one post in them.
Done whenA hand-labelled set of 300 pairs produces a precision/recall curve, and the joining threshold is read off that curve rather than typed in.
Step7~7 daysProduct
The board and the app on the new store

The screen people actually use, reading from a public view of the data that contains only facts about the world. The ordering machine — ranks committed with a tick number so the list cannot shuffle under the cursor — moves across verbatim, since it already works.

UnblocksEverything user-facing, and it is the step that makes the show-facts-not-reasoning rule structural rather than a habit.
Done whenSearching every screen file for our internal scores and gate names returns nothing, and the app is forbidden by rule from importing the thinking layer at all.
Step8~5 daysLearning
The labeller and replay

Joining what we decided to what actually happened — every label carrying the population it was drawn from, so winners and losers are never quietly measured against different denominators. Then the machine that re-runs old decisions under new rules. The existing outcome labeller carries forward: it is the best artefact in the current repository, separating winners at 18× their median peak from losers at 1.19×.

UnblocksEvery model in step 9, and the ability to change a threshold and see who it would have affected before shipping it.
Done whenChanging one number in the thresholds file produces a list of last month's decisions that would have flipped — with no deploy and no network access.
Step9ongoingCalendar-bound
The models

Learned judgement replacing typed numbers, one stage at a time, in the order the labels arrive: the coinable-or-not call first because its label is free and plentiful, then what to watch, then what is accelerating. Ranking last, because it needs a record of what people were shown, and that record does not exist yet. This step is bound by the calendar, not by effort — about 2,000 labelled stories are needed before the first model is worth training.

UnblocksThe compounding advantage. Nothing else in the plan improves on its own once shipped.
Done whenA challenger runs silently alongside the incumbent for seven days and is promoted by a database row, not by a deploy.
Step10~3 daysThe exam
The second platformHighlight 3

One folder for TikTok and one line in a lookup table. The step exists to answer a question about the architecture rather than to add a feature. And it has a specific thing to get right: TikTok has no reproduction count at all, so the connector must declare that concept absent rather than write a zero — which is precisely the bug live in the build today, where every TikTok post reports its most important signal as an honest-looking nought.

UnblocksNothing downstream. What it buys is the answer to whether the previous ten steps were worth doing.
Done whenThe change is one new folder plus one line — and the diff against the thinking layer is empty.

The one place the order can bend

Steps 1 and 5 are the two that repair live defects. If the Buy button matters more right now than the board does, step 5 can jump ahead of steps 3 and 4 with no structural cost — the resolver needs stored mint times, and nothing else from the pipeline lane.

Everything else can slide too. Step 2 cannot, and it is worth saying why one more time: the other ten steps trade weeks for weeks. This one trades weeks for data that cannot be bought, borrowed or reconstructed afterwards. The same logic puts step 1 in the old build rather than the new one — a few thousand judgements a day are being made and thrown away while this deck is being read.

And the step most likely to be cut under deadline is step 10, because by then the product works and a second platform feels like a nice-to-have. Cutting it means never finding out whether the architecture was real — three days from the end of a four-month build.
