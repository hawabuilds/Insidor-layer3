04. Create a coin

An earlier version of this section promised the user would be first. The timing data says that is false for every coin worth being first on. So this screen keeps the same shape and loses the boast: it is the smaller of the two doors, it tells the truth about the odds on the screen itself, and — unlike the build we have today — it actually creates a coin.

The claim we used to make, and why it is dead

X post IDs contain their own timestamp, so the gap between a post going up and a coin being minted from it is computable, not guessable. The median gap is 3.8 minutes, and it shortens as the coin does better: 1.2 minutes above a $1M peak, 1.1 minutes above $10M, with 88% of those minted inside the first hour. Bots watch the same firehose and are faster than any interface with a human in it. Chill Guy — the famous thirteen-month gap — was an archived tweet re-minted years later, and every case like it peaked between $159K and $1.8M. The slow regime is the losing regime.

The second half of that measurement is the good news. Post-to-peak is about six days, and zero percent of coins clearing $1M peaked inside their first hour. The mint window shuts in minutes; the price window stays open for days. That is why buying (section 03) is the main door and this is the side door.

Two different clocks, drawn on one line. Creating is a race we lose in the first ninety seconds. Trading is a race that runs for a week. The product should be weighted accordingly.

So what is this screen actually for

Three honest cases. The story genuinely has no coin — most viral posts never get minted. The user is close to the story and wants to be the one who mints it, for reasons that have nothing to do with beating a bot. Or — the real volume — they have seen the tickers we found, decided none is the real one, and want their own. A pump.fun search for "chill guy" returns 306 distinct tokens. "No coin" almost never means no coin; it means no coin we can match to this story, and the screen should say so.

The example is "Paid to Move to Norway" — a Norwegian town paying €25,000 to people who relocate. 1.1M views, an hour old, nothing trading under any ticker we can tie to it.

The create sheet

One screen. The story sits locked at the top so it is always obvious what this coin is of. Name, ticker and image arrive pre-filled — written an hour earlier as a by-product of the AI reader judging the post, so naming costs nothing extra and is done long before a human turns up. Everything is editable; nothing requires research.

Every figure in that amber block is a fact about pump.fun that would be true if Insidor did not exist. None of it is our scoring. It is the least we can do on a screen that is about to take £155.

A cut of trades afterwards, smaller than the creator's. Stated on the screen where it applies rather than buried in terms.

Test applied to every number here: would it still be true if Insidor did not exist? Views, age, who posted, cost, fee split, share of supply, the pump.fun population statistics — all yes. The judgement that put this story in front of the user stays behind the curtain.

The ticker check has four answers, not two

The check runs while the user is still looking at the field — discovering a collision after a signature is a terrible experience. It is a network lookup against pump.fun, not a look at our own memory, and its honest vocabulary is "nothing trading under this", never "yours".

The fourth card is the one the current build lacks entirely — it cannot fail, because it never asks anyone. A check that cannot fail is not a check.

Signing it

This is where the safety promise is kept. Insidor assembles the transaction and hands it to the user's wallet — Privy, so a specialist handles custody — which shows what is about to happen and asks for approval. We never take custody and never see a private key. Reject it and nothing is spent. The app already does exactly this for buying: api/swap.js builds a Jupiter swap and the browser signs it. Creating should use the same road.

One line does the heavy lifting: the address is read back from the confirmed transaction. It is the mint account the chain assigned, not a string we composed — and the tx signature is shown beside it so the user can check us.

Between tapping Approve and a coin existing there are four outcomes, and the build has one. A blockhash expires in about a minute; transactions get dropped; wallets get rejected; balances come up short once the fee lands. None of these should leave a coin in the interface that does not exist on the chain.

Four states, one of which is success. The build ships the success state only, and reaches it unconditionally.

What the build does today — said plainly

The create flow in the current build does not create anything. Pressing the button invents a contract address with a small random number generator, inserts a token into an in-memory array so it appears in the feed, and tells the user their coin is live. No wallet opens. No transaction is built. Nothing touches Solana. "Copy CA" then puts the invented string on the user's clipboard.

Two more things in the same flow are invented rather than fetched. The availability check at line 653 searches the app's own arrays, then prints "$NORWAY is free on Solana — you'd be first to deploy it" — a sentence about the blockchain produced without contacting it. And the cost line is 0.52 + firstBuy: a hardcoded 0.52 SOL launch fee, roughly twenty-six times the real pump.fun charge of about 0.02 SOL.

The uncomfortable part is that the machinery already exists. api/swap.js builds a real transaction and the token page has the browser sign it through Privy. Buying is real; creating took the shortcut, and nothing in plain JavaScript objected — the same absence of shape that let TikTok play counts get written into a column named views. This is the one bug in the build that could cost a user money on the strength of a number we made up.

Shown here not to embarrass the build but to size the work: the create path is a mockup wearing the interface, and everything above in this section is what replacing it looks like.
