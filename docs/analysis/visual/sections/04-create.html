04. Create a coin

Every other tool shows a coin after it exists. We show the story before it exists — so we can offer something nobody else can: the user makes the coin themselves, from the story, in a few taps, and is first in.

This is the single biggest thing that separates Insidor from Axiom, Photon or GMGN. Those tools are fed by money moving. A coin has to already be trading before it can appear on them, which means every user of those tools arrives after somebody else got there. We are fed by the internet instead, so we see the ferry captain, the plastic plant, the town paying people to move — while the coin is still an idea. At that moment the user has two doors. If a coin exists, they buy it (section 03). If none does, they open this sheet.

The example here is "Paid to Move to Norway" — a Norwegian town is paying people €25,000 to move there. 1.1M views, an hour old, and nobody has made a coin out of it yet.

Where the pre-filled name comes from

The user does not sit and think of a name. The work was already done, about an hour earlier, by a part of the system they never see. When our AI reader looked at this post it was answering one question — could someone realistically make a memecoin out of this? — and part of answering it is proposing what the coin would be called. That suggestion was written down at the time and stored with the story. By the time somebody taps Create, the name, the ticker and the image have been sitting there ready for an hour.

The whole left half of this line happens without anybody asking for it. Naming is a by-product of judging, so it costs nothing extra and it is finished long before a human arrives.

The create sheet

One screen. The story sits at the top so the user can see what they are minting. Everything below it is pre-filled and everything is editable. Nothing here is a decision the user has to research — it is a decision they either accept or nudge.

The story is locked to the top

So it is always obvious what this coin is of. The two-line summary is the same sentence the user read in the feed — no re-writing, no surprises.

Name and ticker arrive filled in

Written an hour ago when the AI judged the post. Tapping Edit replaces them with anything the user prefers; the alternatives are one tap away.

Availability is a live check, not a guess

We ask pump.fun whether the ticker is taken before the user commits. $25K is struck through because somebody already used it.

The image is a still from the post

Three alternate frames plus an upload slot. Most users will accept the first one, which is the point.

The first buy is optional and honest

It says exactly what 1 SOL gets you and what share of the coin that is. Turning the toggle off drops the total to 0.0202 SOL.

One number, in pounds

Crypto interfaces habitually show a total the user has to convert in their head. We show SOL and sterling, and we say plainly that we charge nothing at this step.

How we actually get paid

A cut of trades afterwards, smaller than the creator's. Stated on the screen where it applies rather than buried in terms.

Nothing on this sheet is a number we invented about the story. Views, age, who posted it, the cost, the fee split, the share of supply — all facts the user could verify elsewhere. The judgement that put this story in front of them stays behind the curtain.

Signing it

This step is where the safety promise is kept. Insidor builds the transaction and hands it to the user's wallet. The wallet — provided by Privy, so that the specialist handles the hard part — shows what is about to happen and asks for approval. We never take custody of funds and we never see a private key. If the user rejects it, nothing happens and nothing has been spent.
