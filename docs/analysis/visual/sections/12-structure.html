12. Where the code lives

You told us you could not find the logic in the build we have. That is not a documentation problem, and no README fixes it. The folder names have to answer the question on their own — so the shape below is designed around one measurable test: how long it takes a person who has never seen this repository to open the right file.

The current build fails that test for a specific reason. The place where a post is judged worth coining is worker/adapters/anthropic/meme-score.js — a file inside a folder named after a vendor. It reaches back into worker/score/lib/meme-gate and worker/score/lib/nameability, and it writes the number 0.4 out as a final verdict at four separate line numbers. So the product decision lives in the API-client folder, the thresholds live somewhere else again, and there is nowhere you could have looked that would have been wrong to look. Elsewhere in the same tree, a vendor file and a policy file import each other in a circle, and somebody has already hidden one of those imports inside a function to stop Node complaining. That is not sloppiness. It is the absence of a boundary.

Three layers, and only one of them thinks

The replacement has exactly three layers, and the whole design is one sentence: logic never knows who it is talking to, and vendors never know what the logic decides.

Adapters sit at the edge. Every outside thing — X, TikTok, Reddit, the Solana chain, pump.fun, Dexscreener, Jupiter, Rugcheck, Claude, the embedding model — gets exactly one folder, and that folder's only job is translation: take whatever that service hands back and restate it in our words. An adapter holds no thresholds, makes no product decisions, and contains no SQL. Adding a platform means writing one folder and one line in a registry, instead of forking the pipeline the way TikTok was forked into a second 340-line copy today.

The core holds all the logic, and is pure. No network, no clock, no database, no random numbers, no npm dependencies, and — this is the one that matters most — no platform names anywhere in it. Not views, not retweets, not playCount. Those are X's words and TikTok's words, and the moment they appear in the core, every future platform has to pretend it has them. That is precisely how TikTok's share count ended up in a column called retweets and how quotes — the reproduction signal the whole product rests on — became an honest-looking zero. Pure also means the core is the only part of the system you can replay: hand it yesterday's recorded inputs and it produces yesterday's answer, every time, with no key and no internet.

The record sits underneath. One database, one folder that is allowed to contain SQL, and every decision the core made written down as it happens. And one more wall past that: the app reads a separate, deliberately duplicated wire vocabulary that has no internal field in it, so it is not that the app should not show a score — it structurally cannot obtain one.

Reading down: the outside world comes in on the left of the top band, gets restated in our vocabulary, is judged once in the middle, is written down, and only then is translated back out. The rail down the left is the set of words all four layers agree on. Nothing skips a band.

The whole tree, and what every folder is for

Nine packages. There is no utils/, no helpers/, no types.ts — a junk drawer with a respectable name is still a junk drawer, and within a year nobody can safely delete anything from it. Two naming rules do almost all of the work. First, every stage folder contains a file literally called stage.ts, so "where is the admit logic" has a mechanical answer requiring no search and no memory. Second, every number in the system lives in one file, contracts/policy.ts, and a bare number typed anywhere in the core fails the build. That one is a direct response to the finding that made the last six months unauditable: every threshold in the current system is a number somebody typed, somewhere, and there is no list of them.

The rule, and the fact that a machine checks it

A layered diagram is a wish unless something enforces it, and diagrams like this one have been drawn before and then quietly violated. So the rule is written as a list of who may import whom, and six separate mechanisms refuse a build that breaks it.

Who is allowed to import whomread once — the shape is the whole design
contracts→nothing at all
core→contractsnever a vendor, never a database
adapters→contractsnever core
store→contractsviewnever core, never adapters
view→nothing at all
services→everything — this is the only place things get wired together
app→viewnever core / adapters / store
eval→contractscorestoreviewnever adapters
watchdog→contractsstorenever another service
app must never import core

The product rule is that our reasoning is never on screen. Six surfaces leaked scoring in the last build, and three of them were reasonable-looking UI written against data the browser happened to already have. If the app cannot reach the scoring code, it cannot render a score.

eval must never import adapters

A replay that can reach the internet can look up what happened afterwards. That is exactly how the last validation harness marked its own homework. Removing the ability is cheaper and more reliable than remembering not to.

watchdog must stand alone

The process that tells you the system died must not share code with the system. It runs on a different vendor for the same reason: an observer that shares a failure with the thing it observes tells you nothing at the moment you need it.

Nine lines. If a new person reads only one thing about this codebase, it should be this table — it says both what the pieces are and what they are forbidden to know.

How it is enforced — four layers, cheapest firstall six checks run in under a second
Layer 1
the package manager

The adapters package simply does not list the core as a dependency, so the import fails on the developer's own laptop. This was measured: under npm it silently worked anyway. Under pnpm it dies. That is why the stack says pnpm.

Layer 2
the type checker

One line of config stops someone routing around the rule with a relative path like ../../core. The compiler you already run reports it as an error, with a file and a line number.

Layer 3
the import map

A tool walks every import in the repository against an allow-list — not a list of forbidden pairs, which always misses one, but a list of what each package may reach. It also fails on circles, the exact defect in the build today.

Layer 4
the word check

A leak usually arrives as a field name, not an import. So a script fails the build on any platform, chain or vendor word inside core or contracts — views, retweet, playCount, pump.fun, solana, claude.

$ pnpm check  — types → words → purity → numbers → python → boundaries
$ pnpm test  — including a frozen set of past coins that must still resolve the same way
$ pnpm graph && git diff --exit-code docs/graph.svg
   The last line draws the picture at the top of this section from the actual code and fails if it changed. A changed diagram in a pull request is a signal a non-engineer can read.

The greps stop accidents, not adversaries — which is the correct threat model for a two-person team. The real guarantees are the three layers behind them.

The test: how many seconds to the right file

Here is the actual measure of whether any of this worked. A developer — or you, or a person hired next year — wants to change how a post is judged worth making a coin out of. No README, no search, no asking anybody.

0s
It is a judgement.

Judgements live in one place and that place is called core/. Adapters cannot make one; the store cannot make one; the app cannot see one.

3s
The folders are the verbs.

admit · track · detect · group · qualify · resolve · rank. "Is there a coinable thing here" is qualify. There is nowhere else it could be.

7s
Every stage has a stage.ts.

Not index.ts, not qualifier.ts, not helpers.ts. The rule holds in all seven folders, so it needs no memory.

11s
Open it.

core/qualify/stage.ts — about 120 lines, no network calls, no numbers in it. The numbers it uses are named, and they are all in contracts/policy.ts.

Eleven seconds, three decisions, zero searches. The same walk finds every other judgement in the system, because the tree has exactly one shape.

And two things follow that are worth more than the eleven seconds. Because the file has no numbers in it, changing a threshold is a one-line edit in a file that lists every threshold in the product side by side — you can see what else you are near. Because the file has no network calls in it, you can run the change against every decision the system has already made and see what would have changed, before shipping it. Neither is possible today.

The same question, in the build we have
worker/adapters/anthropic/meme-score.js ← a vendor folder ├─ requires worker/score/lib/meme-gate ├─ requires worker/score/lib/nameability └─ writes 0.4 as a final verdict at 4 line numbers

The product decision is inside the folder named after the model provider. The thresholds it applies live in a third place. Nothing in the folder names points here.

Meanwhile a vendor file and a policy file import each other in a circle, and one of those imports has been hidden inside a function to keep Node from noticing.

The same question, after
core/qualify/stage.ts ├─ imports contracts ← types and thresholds only ├─ no fetch · no clock · no database · no vendor └─ every number named, defined in contracts/policy.ts

The model's opinion arrives as an ordinary field, handed in by the service that called it. If it is missing, the stage abstains with a named reason rather than guessing.

Which means the same file can be replayed over months of past decisions with no key and no internet, and give the same answer every time.

This is the difference the whole section is about. Not tidiness — findability, and the ability to change one number and know what it does.

Why this is worth the discipline

The tree is the documentation, and it is the only documentation that cannot go stale.

A README drifts from the code within weeks. Folder names cannot: the build fails if the code stops matching them. Adapters that import the core do not compile. Numbers typed into the core do not compile. Platform words inside the core do not compile. A person joining in a year reads the tree, not a document, and the tree is true by construction.

None of this is extra work bolted onto the schedule. It is the same code, in different folders, with six one-second checks in front of it — and it is the difference between "add Reddit" being a folder and a registry line, versus what adding TikTok actually cost: a second pipeline, a second set of parsing bugs, and a core signal quietly reading zero.
